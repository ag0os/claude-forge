# The student

Who is being coached. This file is authoritative: if the student corrects any
of it during a session, treat their correction as final and edit **this file**
— never a per-subject copy.

- Senior full-stack engineer, 6+ years of experience
- **Primary language: Ruby on Rails** — fluent, production-grade, has shipped
  real systems at scale: Kafka pipelines, payment infrastructure, streaming
  platforms, agentic AI orchestration
- Knows JavaScript well. **TypeScript is actively being trained up** — a
  beginner to that specific type system, not to programming
- **Python is read-only.** They do not write it. Measured under time pressure:
  Python syntax blocked them on a problem they understood. The useful skill is
  reading and auditing Python an agent writes, not producing it cold.
- **Calibration point, same measurement:** they solved a TypeScript exercise
  unaided, but slowly, on a problem they judged easy. The coding gap is
  *fluency under a clock* — not capability, not comprehension. Train speed,
  and time the sessions.
- Strong daily SQL fluency, but through the ActiveRecord abstraction. Raw SQL
  and query-plan literacy are thinner than the ORM fluency suggests
- Has used MongoDB at smaller scale; wants depth on aggregation pipelines and
  document-design tradeoffs
- Has lived in RSpec-heavy codebases for years; TS testing patterns are less
  practiced
- **~18 months of heavy AI-assisted workflow.** Concepts are still solid;
  specific API surface and method names have gone blurry. Has been accepting
  agent-written code without always checking whether it is idiomatic.

## AI engineering

Not a side interest — the direction they want their engineering to go.

- **Builds custom agent orchestration harnesses** and uses them daily to do
  their own engineering work. This is real production-shaped experience with
  agent loops, tool design, and context management, not hobby tinkering.
- **Holds the Anthropic Certified Architect (Foundations) certificate**, as of
  2026-08. Assume that vocabulary and go past it; do not re-teach it.
- **Thin on RAG/retrieval and on evaluation.** Can define the terms, has not
  built either in production. These are the two real gaps in an otherwise
  strong AI profile.
- Prefers designing AI systems over conventional application engineering.

## Goals

- Become stronger at engineering broadly
- **Restore manual coding fluency** — write correct code cold, at speed,
  without reaching for an assistant. Reframed after Andrew Ng's AI Engineering
  Skills Map: the target is not out-typing an agent, it is knowing what the
  agent got wrong and being able to steer it in the precise language of
  engineering tradeoffs.
- Hold senior-level system design as a standing capability rather than
  something re-learned when needed
- Keep architectural judgment sharp and current — Rails, TypeScript, and the
  agnostic layer above both
- **Move toward AI systems work** rather than conventional application
  engineering
- Build toward the four skills on Ng's map — building/deploying AI apps,
  software engineering fundamentals, using coding agents, and shaping the
  build — as a career shape. This is an explicit request from the student, not
  an inference.

## Top weak spot — applies in every subject

**Blocking under pressure**, driven by impostor syndrome and the AI-reach
reflex. This is a first-class training axis, not a footnote. It shapes how
every session runs even when it is not the stated focus.

In territory with no compiler — architecture, design, product judgment — the
same weak spot inverts and shows up as **hedging**: surveying options instead
of recommending one. A recommendation defended and then revised under good
argument is the target; a survey is the failure.

## Calibration

- Skip programming fundamentals, algorithms-as-concepts, and general software
  design. Those are not the gap.
- The gap is at the level of *write it from memory, fluently, under time
  pressure, without reaching for an agent.*
- Never treat them as a beginner in Ruby or Rails. **Do** treat them as a
  genuine beginner in TypeScript's type system and Python's standard library.
  The subject pack's **Stance** field says which applies here.
- Never treat them as a beginner in agent orchestration either — meet them as
  a practitioner there and argue rather than explain. Retrieval and evaluation
  are the exceptions, and those are genuinely new ground.
- They dislike puzzle-shaped exercises and prefer work shaped like real
  developer tasks. Both are trainable; lead with the practical framing.
